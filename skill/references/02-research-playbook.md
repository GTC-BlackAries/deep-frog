# 调研执行手册

> 并行编排的具体打法、agent prompt 模板、交叉核验问法，以及踩过的坑。

## 一、编排选择：先判断该走哪条路

### 先按决策分量定档（不要一律五路）

五路并行是重武器，**只有在真要下注时才值得**。判断的实质是：
**这个结论错了，我要付多大代价。** 答错了顶多"知道错了"，就不该启动。

| 决策分量 | 开几路 | 是否出 HTML | 是否跑两个脚本 |
|---|---|---|---|
| 真要下注（钱 / 时间 / 方向） | 五路 | 是 | 是 |
| 中等（选型、续费、某个说法） | 2–3 路 | 不必 | 不必 |
| 小（一个已有确定答案的事实） | 0，直接搜 | 否 | 否 |

定完档再看下面的情形表。

| 情形 | 编排 | 理由 |
|---|---|---|
| 陌生领域，只需快速摸清大盘 | `domain_search` 托管代理，1 次调用 | 它是多源聚合 + 综合，成本高但省时。**适合"大概知道长什么样"** |
| 需要追口径、纠误引、找矛盾 | **并行 agent + 主线程 WebSearch** | 托管代理做不到反复追问与纠错往返 |
| 已有明确子问题清单 | 直接 WebSearch 串行 | 几件事而已，不必上编排 |
| 需要产出可交付文档 | 无论哪条路，产出侧都要走第 5–6 步 | — |

**注意**：`domain_search` 的描述明确要求"单句、高层级的搜索意图"，
不要把字段清单塞进 query。

## 二、多路并行的拆法

### 拆解原则：按证据类型拆，不按问题清单拆

同源验证没有意义。两路 agent 都查同一批网站，交叉核验就白做了。

**五路标准配置**（按领域调整第 3 路）：

| 路 | 职责 | 主要证据类型 | 典型产出 |
|---|---|---|---|
| A | 市场规模与需求 | 统计 / 研究报告 | 规模、增速、渗透率、基数、人口 |
| B | 供给与竞争 | 企业公开信息 | 玩家、份额、产品线、价格带、渠道、融资 |
| C | 一手依据 | **按领域替换** | 医疗→试验/指南；软件→实测/源码；消费→用户评论 |
| D | 政策与合规 | 政府文件 | 标准、法条、监管口径、处罚案例、时间表 |
| E | 工具与形态 | 产品实测 | App 形态、收费、留存、下载量、变现路径 |

### 关键：路 C 要按领域换模板

- **医疗/健康**：RCT、指南、共识、流行病学
- **软件/工具**：实测、官方文档、Issue/更新日志、定价页
- **消费/品牌**：SKU 矩阵、价格带、电商销量、用户评价
- **金融**：财报、招股书、监管披露、研报
- **政策/公共**：文件原文、立法进程、执行案例
- **采购 / 签约**：定价页、合同条款、司法与被执行记录、资质证照、更新日志（看活跃度）

### 场景「要不要信」：不开五路，只跑 SKILL.md 第 4 步

核验一个说法 / 一份报告 / 一组数据时，**不要拉五路 agent**。
正确做法是把查误引单独当主线，顺着下面五问逐条追原文：

1. 这个文献 / 数据源**真的存在吗**（题名 + 作者 + 年份 + 期刊四件套对得上）
2. 结论是**全量分析还是某个子集**（ITT vs per-protocol 是最常见的坑）
3. **有没有被省略的另一半**（退出率、副作用、适用人群限制）
4. 适用范围**有没有被外推**（高危人群 → 普通人；实验室 → 真实世界）
5. **是谁在引用它**，引用时口径有没有被改

这一路成本最低、回报率最高：一个假数字会污染后面所有基于它的决策。
交付不用出 HTML，在对话里给「判定 + 出处 + 存疑点 + 该向谁核实」四段即可。

### 每路 agent 的 prompt 必备七要素

缺一条，这路就废了：

1. **自包含**——agent 看不到主线程对话，任务背景要写全
2. **分块要求**——明确列出要覆盖的 5 个方面
3. **具体度要求**——"给具体数字、公司名、账号名、URL，不要泛泛而谈"
4. **区分确证与未查到**——"每条结论标注【已确证】或【未查到公开数据】"
5. **证据等级**——"A=指南/RCT/官方统计，B=队列/机构口径，C=专家意见/企业资助"
6. **禁止编造**——"查不到就写未查到，**不要用估算填空**，不确定的标注为推断"
7. **末尾产出要求**——"最后一节给出可执行判断，每条说清谁在做/为什么没被吃掉/要什么资质"

### Agent prompt 模板

```markdown
你是一个只做只读调研的子代理。任务：<一句话目标>。
不要写文件、不要改代码，只返回结构化结论 + 来源链接。

请调研以下问题，尽量给具体数字、具体名称、具体时间点，并附 URL：

1. <问题>
2. <问题>
3. <问题>

输出要求：
- 用中文，分 <N> 块对应上面 <N> 个问题
- 每条结论标注证据等级 A/B/C
- **明确区分「已确证」与「未查到公开数据」**——不确定的标注为推断
- 最后加一节「<产出物名>」，列 <M> 条，每条说清楚 <三个要素>
- 不要输出空泛套话，要具体
```

## 三、主线程对抗式交叉核验

**不要等所有 agent 结束再验。** agent 一返回就并行开 WebSearch 查同一批话题。

目的是**找矛盾**，不是复核。四类必查：

### 0. 先给自己设预算（这条别跳过）

主线程亲自下场核验是有代价的——**它会污染主线程上下文，而且没有天然的停止点。**
同类 skill 里有一派干脆明令"协调者不得接触原始证据"（把核验外包给 subagent），
我们反其道而行，所以**必须从别处把控制权找回来**：

- 主线核验的轮次要有**显式上限**（写进任务清单，比如"核验不超过 N 轮"）
- 命中下面的"停下来问人"规则时立刻停，不要硬查
- **核验环节失败（限流 / 报错 / 崩了）记 unverifiable，不记 refuted**
  ——见 `01-caliber-evidence.md` 的三态纪律

### 0.5 停下来问人的时机：冲突时，不是开头时

一上来问几个澄清问题没什么用。**真正必须问人的是这一刻：
调研结果和用户已经给过的事实、或者和用户已有的资产相冲突时。**

| 触发情形 | 动作 |
|---|---|
| 查到的数字和用户手里的台账对不上 | **停下**，把两个值都摆给用户，让他拍板哪个为准 |
| 调研结论与用户已有 skill 的结论相反 | **停下**，不要静默覆盖用户资产里的说法 |
| 某个关键数字两个来源打架且无法判定 | 并列写进"口径冲突"表，标注"需向 X 核实" |

**绝不静默覆盖用户给过的事实。** 覆盖 = 用户以后再也不知道自己原来的数是怎么没的。
门禁不通过时**定向回补那一条**，不要推倒重来。

### 1. 规模口径

问自己：
- 这个数字含不含我研究的对象？（1095 亿"防敏市场"**不含**辅食）
- 零售额还是出厂额？
- 年份一致吗？（两份报告差 2 年 = 不可比）
- 是官方统计还是研究机构估算？

### 2. 关键数字的定义

同一个词在不同来源可能是不同东西：
> 「患病率」：自报 40.9% vs 确诊 2.5% vs 检出 8.4% vs 激发确诊 7.7%

**必须问：分子分母各是什么、怎么测的。**

### 3. 争议结论的另一半

agent 说某干预有效，你要去查：
- **退出率 / 脱落率**（坚持不下去的人算不算）
- **副作用 / 反效果**
- **适用人群限制**（高危 vs 普通）
- **ITT vs per-protocol**（ITT 阴性但 PP 阳性，是最常见的陷阱）

### 4. 被广泛引用的说法

去搜"这个说法有没有被推翻/被取代"。

> 实例：某研究被反复转述为"早期引入过敏原可预防过敏"，
> 实际它的 **ITT 分析为阴性**，阳性来自 42% 依从者的子集——
> 而 meta 分析同时显示**退出率翻倍**。只转述前半句就是误导。

### 深水模式：要不要请一个挑刺者（critic）

主线程自己核验有个结构性弱点：**它看得见自己的推理过程，所以很难怀疑自己的起点。**
想更彻底就得请挑刺者，但**光是"再开一个子 agent"不算独立**——那只是换了个执行者。

独立性由三件事决定，缺一件就等于白请：

| 条件 | 错的做法 | 对的做法 |
|---|---|---|
| **输入隔离** | 把调研成果连推理过程一起给它 | **只给结论清单**，让它自己去查，不接触主线程的中间材料 |
| **prompt 中立** | "请验证以下结论是否正确" | "**逐条试图推翻**，写清你用什么办法推翻的；推翻不了的要写明'试图推翻未成功'" |
| **产出不可逆** | 产出回到主线程，可以被悄悄删掉 | critic 指出的问题**原样进报告**，主线程只能标注采纳情况，**不得改字、不得删条** |

第三条是整套东西的命门。**没有它，前两条只是表演。**

#### 落地方式

1. critic 的产出先落成独立文件 `{工作区}/critique.md`，不进主线程的内存就删掉
2. 报告里必须有「**通过核验与被质疑**」一节，把 critique 的条目**逐条原样**列出
3. 主线程在每条右侧标注 `采纳 / 不采纳 + 理由`。**不采纳也要写为什么**
4. `audit_report.py` 负责检查这节存在且条数与 critique.md 一致（对不上就是 ERROR）

#### critic prompt 模板

```markdown
你是一个独立的挑刺者（critic）。你没有参与之前的调研，也不知道调研者的推理过程，
这是刻意设计的——你的价值就在于不知道。

下面是本次调研得出的 <N> 条核心结论。对每一条，请**主动尝试推翻它**：

1. 去找能反驳它的证据、数据来源或反例
2. 检查它的口径是否成立（分子分母、统计方法、时间、样本代表性）
3. 检查有没有被省略的另一半（退出率、副作用、适用人群限制）
4. 检查参考文献是否真的存在、结论是否被误引

输出要求：
- 用中文，逐条对应
- 每条给出判定：**REFUTED**（推翻成功）/ **HELD**（试图推翻未成功）/ **UNVERIFIABLE**（查不到，无法判定）
  ——**注意：你自己查不到不等于该结论错误**
- 推翻成功的，给出具体证据与 URL
- 最后加一节「被漏掉的东西」：你认为哪些该查却没人查
- **查不到就写查不到，不要用推测填空**
```

> **成本提醒**：这一趟不便宜。默认不开，只有决策分量落在"真要下注"档时才值得。
> 中小决策走标准模式（主线程自己核验）完全够，不要为了显得严谨而追加成本。

### 矛盾怎么写

**进报告的"口径冲突"表，不要私下换数字。** 表格列：数字 A / 数字 B / 各自出处 / 各自口径 / 可信度 / 结论（不可调和 / 可解释 / 需向 X 核实）。

## 四、非领域场景怎么裁剪报告形态

SKILL.md 第 5 步那张章节表是**领域调研的默认形态**，不是每类场景都要照抄。
判断标准很简单：**这一章会不会影响那个决策。** 不影响就删。

| 场景 | 保留 | 删掉 | 补上 |
|---|---|---|---|
| 要不要投入（领域版） | 全部 | — | — |
| 要不要信（核验） | 一句话结论、证据与争议 | 规模、政策、竞争格局、机会判断 | **质疑清单**、该向谁核实 |
| 要不要买 / 签 | 一句话结论、口径冲突、风险未解 | 规模与需求、政策与合规 | **退路与迁移成本**、谈判要点 |

**两处必须跟着改的变量：**

1. **第 1 步的"决策意图"**——从"要不要做"换成"要不要信 / 要不要买 / 要不要签"。
   这一项换了，后面的删章才有依据。别的都别动。
2. **第 0 步读的"存量资产"**——核验场景读待核验材料本身；
   采购场景读用户当前用法、履约到期时间、换掉要付的成本（迁移成本常常才是决定性数字）。

**不要为了看起来完整而加回删掉的章节。** 那份丰盛感是给投资人看的，不是给决策者看的。

## 五、外部环境约束（已知事实，不要重写一遍）

### 约束 1：Edge/Chrome 无头截图的三个坑

| 现象 | 解法 |
|---|---|
| 中文文件名 → `ERR_NAME_NOT_RESOLVED`（URL 被编码成 punycode） | 复制成 ASCII 副本再截 |
| `scrollTo` 无效 → 滚动后截出空白页 | 按 `<h2 id=>` 拆成独立章节页分别截 |
| 最小窗口宽度约 500px → 截 420px 出现"内容溢出"假象 | 窄屏验证用 ≥560px |

**`scripts/render_check.py` 已内置这三个规避**，不要手写截图流程。

### 约束 2：`--screenshot` 的值不能带引号

```python
# ✗ subprocess 不会像 shell 拆引号，整个带引号的字符串被当成字面路径
'--screenshot="%s"' % out_png
# ✓
'--screenshot=%s' % out_png
```

这个坑的表现是**截图静默失败**（文件不生成），不报错。

### 约束 3：环境可能没有可用的 Python

Windows 应用商店版 `python.exe` 是占位符（`python --version` 无输出、直接 exit 1），
**这不算装了 Python**。本 skill 的两个脚本**只用标准库，不需要 pip 安装任何包**，
但仍要求 Python 3.8+。

处理方式见 SKILL.md 第 6 步：**先探测，再决定走脚本路径还是人工核对清单路径**。
**不许静默跳过自检**。

### 约束 4：不要引入 PIL 依赖

审计与渲染脚本只用标准库（PNG 尺寸用文件头解析）。PIL 在很多环境装不上，
引入它等于让整个自检步骤依赖一个可选组件。

## 六、终止条件

什么时候算调研够了？

- [ ] 决策意图对应的核心问题都有答案了吗？
- [ ] 每个关键数字都有口径了吗？
- [ ] 冲突数字都查清来源了吗？
- [ ] 关键论断都追到原文了吗？
- [ ] 查不到的部分都列进"未解缺口"了吗？
- [ ] 有没有**意外发现**（口径错位、标准真空、玩家断层、某条被证伪的共识）？

> **意外发现往往比预期结论更有价值。** 它通常来自"本地数据 vs 国际标准""中国口径 vs 海外口径"
> 这类对照——**错位只有对照才看得见**。写报告时优先保留这类发现，它们比市场规模更有决策价值。
