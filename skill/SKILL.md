# 深蛙

> **凡是要下注的问题，先把证据收拾干净。**

**作者**：GTC黑羊 · ToolRadar.cc · License MIT（见 `LICENSE`）

"深蛙"是"深挖"的谐音。选这只蛙还有一层原因：**蛙会叫**——
这套纪律最要紧的一条就是"查不到、有冲突、拿不准时必须出声"。
一只闷头挖、挖到什么都不吭声的鼹鼠，恰恰是这份 skill 要避免的东西。

凡是含糊地问"某某到底怎么样"的任务，都归它管：
一个赛道、一款工具、一家供应商、一份报告、一个到处流传的说法。

本 skill 是**元技能**：它不绑定任何具体领域，沉淀的是一套可复用的调研纪律。
领域知识随任务加载，纪律永不加载。

## 核心信念

**一份调研报告最贵的错误不是写错观点，而是把一个口径不对的数字、一个不存在的文献、
或一个被误引的结论当成事实写进交付物。** 观点错了读者会质疑，数字错了读者会照着做决策。

因此本 skill 的产出重心不在"信息量"，而在**可信度**：
哪些是确证的、哪些是推断的、哪些查不到、哪些数字互相打架——全部摊开写。

## 四条不可协商的纪律

1. **口径先于数字。** 任何数字必须带口径：分子分母、统计方法（自报/确诊/检出）、
   是否含某品类、零售额还是出厂额、年份、样本量。**没口径的数字不许写进正文。**
2. **冲突不调和。** 两个来源打架时**并列写出**（标注各自的出处、口径、可信度），
   不许挑一个顺眼的用，不许取平均，不许只写"约"。打架本身就是信息。
3. **查不到就写查不到。** 明确列入"未解缺口"，**绝不用估算填充**。缺一个数字比错一个数字安全。
4. **冲突必须先问人。** 调研结果和用户给过的事实、或和用户已有资产相冲突时，
   **停下来问，绝不静默覆盖**。用户是以此为基准做下一次决策的，
   悄悄改掉他的基准，比查错一次数字严重得多。
   核验没跑通（限流/报错）记 **unverifiable**，不许记成"已证伪"——工具故障不是研究发现。

配套要求：证据分级（A/B/C）、误引必查、免责声明与未解缺口章节不得缺失。

## 适用边界：什么任务该用它

**判据不是"这是不是一个领域"，而是"答错了会不会花掉钱、时间或方向"。**
凡是要拿结论去下注的，这套纪律就值。领域调研只是第一个被磨出来的用法。

本 skill 真正卖的四件事与具体领域无关——收敛边界、按证据类型多路并行、
主动找矛盾、把不确定显式写出来。所以它可以迁移，**迁移时通常只换一件东西**：
第 3 路（C 路）装什么样的"一手依据"。

| 场景 | 触发问题长这样 | C 路换成 | 第 0 步读什么 | 反哺清单变成 |
|---|---|---|---|---|
| **要不要投入**（赛道 / 产品线 / 副业 / 投资初筛） | 这个赛道值不值得进 · 这条产品线要不要砍 | 按领域替换，见 `02-research-playbook.md` 第二节 | 用户现有 skill / 业务台账 | 对用户现有业务的行动建议 |
| **要不要信**（说法 / 报告 / 数据核验） | 这个被反复转述的共识是真的吗 · 这个数字出处在哪 | **第 4 步（查误引）升级为主线** | 待核验的那份材料本身 | 质疑清单 + 该向谁核实 |
| **要不要买 / 签**（工具 / 软件 / 供应商 / 合作方） | 这套 SaaS 续不续 · 这家供应商可靠吗 | 一手凭证：定价页、合同条款、司法记录、资质、更新日志 | 用户当前用法 / 履约状态 / 迁移成本 | 谈判要点 + 迁移清单 |

**"要不要信"这一类是成本最低、回报率最高的一类**：它不用跑全套，
把第 4 步单独拎出来当主线即可，交付也不用出 HTML。原因很简单——
一个假数字会污染后面所有基于它的决策。

### 减配：不要每次都全套

| 决策分量 | 编排 | 交付形态 |
|---|---|---|
| 真要下注（钱 / 时间 / 方向） | 五路并行 + 主线程对抗核验 | 自包含 HTML 档案，完整走第 5–6 步 |
| 中等（选型、续费、某个说法） | 2–3 路 + 主线程核验 | 聊天里结构化答复，不必出 HTML |
| 小（一个已有确定答案的事实） | **不启动本 skill** | 一次搜索直接答 |

### 三类别用它

1. **查一个已有确定答案的事实**（"XX 现在多少钱"）——走流程纯属浪费。
2. **写文案、想创意**——纪律要求"不许编"，与创意天生打架。
3. **已经想清楚只差动手**——别拿调研当拖延。

### 但还有一种情况：你手上还什么都没有

**没有候选的时候不要硬开本 skill。** 它的输入是"一个待验证的候选"，
如果你现在连候选都没有（"我不知道做什么""帮我找个方向"），
强行跑只会得到一堆被自己的纪律提前否掉的空话——
**想法刚冒头时最缺证据，这时候上验证纪律等于先把灯关掉。**

这种情况走上游：**`tadpole`（蝌蚪）**，它是本 skill 的前段，负责生成候选。
蝌蚪产出 30 颗种子后按"依赖前提"聚类，排出 3–5 颗短名单交棒给本 skill。
两者是同一条链的两截，分开是因为纪律方向相反——
蝌蚪要求"发散时不许否定"，本 skill 要求"必须否定"，塞进一个流程会互相抵消。

> **一句话记住分工**：蝌蚪负责让你有东西可判，深蛙负责判它生死。

> **前置条件（使用前须知）**：`tadpole` 是**另一个独立技能**，需另行安装。
> 若用户机器上未安装蝌蚪，**本 skill 的"要不要投入"这一类仍可正常使用**——
> 只要用户手上已经有一个待验证的候选（一个方向、一个说法、一份报告、一个供应商）。
> 蝌蚪只负责"从零生成候选"这一步，与深蛙的核验能力无关。
> 未安装时如实告知用户「蝌蚪未安装，无法从零生成候选；你已有候选的话，深蛙可以直接开跑」——
> **不要假装它存在，也不要因此拒绝执行用户已经明确的任务。**

> **副作用要提前说**：这套流程**变慢**，且给出的答案**没那么痛快**——
> 它会不停跳出"这个数字口径不对""这个说法已被推翻"。
> 想要一个爽快结论的时候别开它。它的价值在于三个月后不会因为一个假数字后悔。

## 执行流程

### 第 0 步：读存量资产（最容易被跳过，也最关键）

在开题之前，先读用户已有的相关资产：现有 skill、文档、台账、过往报告。

```
Glob  ~/.workbuddy/skills/*/SKILL.md      # 用户级 skill
Glob  {工作区}/.workbuddy/**            # 工作区记忆与日志
Read   命中 skill 的 SKILL.md + references/
```

读完要能回答：**用户手上已经有什么？本次深挖与它是什么关系？**

为什么必须做：
- 用户已有资产往往**已经隐含了本赛道的关键判断**（哪怕它自己没意识到）。
  不读就写，产出会是一份与用户实际处境脱节的通用行业报告。
- 读完之后才能给出**反哺清单**（见第 5 步）——这是本次交付相对普通调研的唯一增量。
- 能避免"你的 skill 里已有这个结论，我又重新查了一遍"的浪费。

若用户已有相关 skill，其知识体系（国标/指南/口径）就是本次调研的**高权重来源**，
可直接引用；注意它的缺口——**已有资产的口径可能与本赛道现实不符**，需要外部核验。

### 第 1 步：定义研究问题（不是定义报告结构）

先写清楚：**这次深挖要回答谁的什么问题？**

三个必答项：
1. **决策意图**——用户拿到报告后要做什么决定？（做产品？投钱？进不进这行？写内容？）
2. **范围边界**——含什么、不含什么。规模要不要含上下游？要不要含海外？
3. **对标物**——跟什么比？跟同类赛道比？跟用户现有业务比？

若用户只说"深挖一下 X"，按默认：**当决策意图为"我要判断要不要做/怎么做"，
范围取"中国市场为主 + 海外对标"，对标物为"该领域内的现有玩家 + 用户现有资产"**。
默认写在报告开头，不要默默假设。

### 第 2 步：拆解调研维度（决定并行结构）

按**证据类型**而非问题清单拆。每个维度派一路 agent：

| 维度 | 典型内容 | 证据类型 |
|---|---|---|
| 市场规模与需求 | 规模、增速、口径、基数、渗透率 | 统计/研究报告 |
| 供给与竞争 | 玩家、份额、产品线、价格带、渠道 | 企业公开信息 |
| 证据与机制 | 试验、指南、共识、争议 | 学术文献 |
| 政策与合规 | 标准、法条、监管、处罚案例 | 政府文件 |
| 工具与形态 | App/产品形态、收费、留存 | 产品实测 |

**通用性提示**：非医疗/非金融领域，把"证据与机制"换成该领域的**一手依据**
（如实测数据、原始文献、官方文档、源码）。核心是"每路负责一种证据类型"，
这样交叉核验才有意义——同源验证无意义。

**每个 agent 的 prompt 必须包含**（缺一条这路就废了）：
- 自包含（agent 看不到本次对话）
- 明确要求**区分"已确证"与"未查到公开数据"**
- 要求给具体数字、公司名、URL
- 要求标证据等级
- **明确禁止编造**："查不到就写未查到，不要用估算填空"

### 第 3 步：主线程对抗式交叉核验（不要等 agent）

**agent 返回后立刻开始，同时自己开 WebSearch 查同一批话题。** 不要等所有 agent 结束再验。

目的不是复核，是**找矛盾**。同一问题两边数字对不上，就是有问题的信号。

必查项：
- **市场规模的口径**——含不含某品类？零售额还是出厂额？年份一致吗？
- **关键数字的定义**——"患病率"是自报还是确诊？是检出率还是发病率？
- **争议结论的另一半**——agent 说某干预有效，去查它的**退出率/副作用/适用人群限制**。
- **被广泛引用的说法**——是否已被证伪或被更权威的版本取代？

抓到的每一条矛盾，写进报告的"口径冲突"表，而不是悄悄换一个数字。

> **深水模式**：决策分量在"真要下注"档时，可额外起一个独立 critic 做挑刺。
> 但注意——**用子 agent 不等于独立**。独立性靠三件事：只给它结论清单（不给你的推理）、
> 让它逐条试图推翻、以及**它的产出不许被你删改**（原样进报告，你只能在旁边标采纳与否）。
> 详见 `02-research-playbook.md` 第三节末尾。中小决策不需要这一趟。

### 第 4 步：查误引（这一步能救掉整份报告）

被广泛传播的"共识"经常是**二手简化版**，且**张冠李戴**极其常见。
每个进入正文的关键论断，动手前先确认：

```
1. 这篇文献/试验真的存在吗？→ 检索标题 + 作者 + 年份 + 期刊，多路交叉
2. 结论是 ITT 还是亚组/per-protocol？→ 看原文分析集
3. 有没有被省略的另一半（退出率、副作用、适用人群）？
4. 结论的适用范围是否被外推了（高危人群 → 普通人群；实验室 → 真实世界）？
5. 是谁在引用它？引用时有没有改口径？
```

**存疑的引文若仍要写入正文，必须在正文里标注"存疑/未查到原始出处"，
并在审计脚本中豁免（脚本认得这些标记）。** 不要因为"大家都这么说"就照抄。

发现文献不存在、或题名/年份/期刊错配时，**在报告里单列一节纠正**——
这往往比正文结论更有价值，也最能建立可信度。

### 第 5 步：结构化产出（自包含 HTML）

默认交付**单文件 HTML**（内联 CSS、字体本地打包、无外部依赖），
聊天正文只留 3–5 行摘要 + 文件路径，长表格放 HTML。

推荐章节（按重要性调整，但**这四项不得缺**）：

| 章节 | 作用 |
|---|---|
| 一句话结论 | 读者只看这段也能行动 |
| 赛道坐标/定义 | 明确研究对象与边界，澄清术语混淆 |
| 规模与需求 | 每个数字带口径，冲突数字并列 |
| 证据与争议 | 分级呈现，正反并列 |
| 政策与合规 | 能做什么/绝对不能碰 |
| 竞争格局 | 玩家矩阵 + 谁在抢什么概念 |
| 机会判断 | 每条含：谁在做/为什么没被吃掉/要什么资质 |
| 风险与未解缺口 | 查不到的部分显式列出 |
| **对用户存量资产的反哺** | 逐条对照已有 skill/文档，可直接执行 |
| 参考文献 | 分组，按用途 |

**反哺清单是本 skill 的差异化产出**，写法要求：
- 逐条对照用户已有文件的**具体位置**（如"「致敏食物清单.md」把芒果归入八类之外"）
- 每条给出**发现 → 对现有资产意味着什么 → 建议动作**三段
- **不要擅自修改用户的 skill**——医疗/法律/金融类内容改动需用户拍板

视觉规范见 `references/03-report-design.md`。没有用户专属视觉规范时，默认使用 **Deep Frog Brand System**：深色品牌侧栏与 Hero、浅色阅读正文、薄荷绿品牌强调色，并使用 `assets/deep-frog-logo.png` 官方 Logo。生成 HTML 时将 Logo 内嵌为 data URI，保持单文件图像可用。
若用户已有 skill 或项目明确规定了视觉规范，**用户的规范优先**，不要强行套用 Deep Frog 默认皮肤；不得自行重绘或替换官方 Logo。

### 第 6 步：交付前自检（脚本优先，无 Python 时走人工清单）

> **运行条件（使用前须知）**：本步骤的自动审计需要 **Python 3.8+**（仅用标准库，无需 pip 安装任何包）。
> 若运行环境没有 Python，**这不是错误**——请改走下面的「人工核对清单」路径，自检仍然要做，只是由你逐项核对。

**先探测，再决定走哪条路**：

```bash
python --version    # 拿到版本号 → 走 A；报错/占位符/无输出 → 走 B
```

> ⚠️ **Windows 应用商店版 `python.exe` 是占位符**：`python --version` 拿不到版本号、直接 exit 1，
> **这不算装了 Python**。此时不要重试、不要尝试 `py` 启动器，直接走 B。

| 路径 | 条件 | 做法 |
|---|---|---|
| **A · 脚本审计** | Python 3.8+ 可用 | 跑下面两个脚本，**ERROR 必须清零** |
| **B · 人工核对** | 无 Python | 用 `references/04-manual-checklist.md` 逐项核对，**同样不可跳过**；在交付说明里写明「本次为人工核对」 |

**路径 A · 脚本审计**：

```bash
# 数字与引用的静态审计——ERROR 必须清零
python scripts/audit_report.py {报告路径}

# 渲染验证——分章截图 + 桌面/窄屏双视口
python scripts/render_check.py {报告路径}
```

两个脚本都是纯静态/本地运行，不需要联网。

`audit_report.py` 检查：裸数字（缺口径）、伪精确、引用不可追溯、
结论型数字缺证据、必备章节缺失、外部资源依赖、死链、缺窄屏/打印样式。

`render_check.py` 检查：逐章截图，确认无空白页、无布局塌陷。**它自动规避了三个
已知的无头浏览器坑**（中文文件名 URL 编码失败、`scrollTo` 无效、Edge 最小窗口宽度），
不要重写一遍。

**WARN 项要人工看**，多数是"提醒补口径"而非错误；ERROR 才是硬伤。

## 行为红线（任何时候不可越）
- **不越权下结论**。涉及医疗、法律、金融的领域，产出是**调研材料**不是决策；
  报告首尾必须有免责声明，且不替代专业意见。
- **不擅自改用户的资产**。反哺清单是建议，不是执行。
- **不追热点**。不为了"完整"而纳入与决策意图无关的维度。
- **不夸大本 skill 的能力**。多路并行调研、数字冲突并列呈现、查不到必须登记，
  都是公开的通用做法，**不要写成"本 skill 首创"**；
  唯一值得主张的是「**每个数字都带口径**」这一条。其余按"叠加了口径层"或"一种取舍"来陈述。
